# Игровые тесты helluvia01

Команды запускаются из корня проекта в PowerShell.

```powershell
.\testing\test.cmd
.\testing\test.cmd --scenario .\testing\scenarios\ember-cooldown.json
.\testing\test.cmd --all
```

Первая команда выполняет контрольный выстрел из `helluvia01/smg`, вторая запускает один сценарий, третья — все JSON из `testing/scenarios` последовательно. Путь после `--scenario` считается от текущего каталога. Код возврата 0 означает, что все выбранные игровые проверки прошли. Во время запуска нужен обычный сеанс Windows с доступным экраном и работающей установкой Steam/tModLoader.

Стенд обнаруживает установку по соседнему `..\tModLoader.targets`, проверяет SDK 8 и целевую платформу загрузчика. Пути можно переопределить через `--tml` и `--saves`. Для запуска на другой машине нужен Python 3.11+ и Pillow. Для резервного захвата по HWND нужна версия Pillow с поддержкой `ImageGrab.grab(window=...)`. Скрипт `test.cmd` ищет локальную установку Python 3.14, затем использует `py -3`. Можно напрямую вызвать `python testing/run.py` тем же интерпретатором. Python фиксирует доступность PyAutoGUI. Атаки и горячие клавиши подаются игровому клиенту без глобальных кликов в Windows.

## Сохранения и сборка

Каждый запуск создаёт отдельную папку `helluvia-test-*` в `%TEMP%`. Чтобы хранить результаты дольше, передайте `--output-root D:\TerrariaTestRuns`. Каталог результатов должен располагаться вне `ModSources`.

В `backup/` сохраняются файлы только `Players/ModTester` и `Worlds/ModTestWorld`, включая сопутствующие данные tModLoader, имеющиеся резервные версии и карты персонажа. SHA-256 исходных файлов и резервной копии сверяются после завершения. Клиент открывает рабочие копии из `profile/` с параметром `-tmlsavedirectory`. Для входа требуются совпадающие имена внутри сохранений, локальные пути и совместимые режимы сложности. Если сохранений нет, подготовка завершается с указанием отсутствующего файла.

Установленный tModLoader собирает два `.tmod` из копий исходников. В профиле включаются `helluvia01` и отдельный `HelluviaTestHarness`. Для обычной сборки мода каталог `testing/` исключён через `build.txt` и `.csproj`. Сборка и запуск стенда не требуют изменений в пользовательском `Mods/enabled.json` или Hero’s Mod.

## Что проверяют готовые сценарии

| Файл | Измерения |
| --- | --- |
| `smg.json` | Проверка выбранного слота и 10 мушкетных пуль. Один тик нажатия. Начало анимации, две скоростные пули и две вспышки, игрок-владелец, источник-оружие и ID патрона. После атаки допустимо 9 или 10 патронов. |
| `melee.json` | Выдача меча, расходников и Shackle. Экипировка повышает защиту на единицу относительно измерения без аксессуара. Удар мечом регистрируется для созданной мишени, урон положителен, здоровье мишени уменьшается. |
| `ember-cooldown.json` | Первый залп даёт семь дробин. Пока действует cooldown, повторное нажатие блокируется. После смерти и штатного возрождения отсчёт продолжается. После истечения таймера второй залп доводит число дробин до 14. |
| `controls.json` | Подача `Terraria/QuickBuff`, расход зелья, появление баффа Ironskin. Удержание правой кнопки и проверка типа снаряда альтернативной атаки Sky Dragon’s Fury. |

## Как добавить сценарий

Скопируйте подходящий JSON из `testing/scenarios`, задайте `name`, `mechanic`, фактические начальные условия и `timeoutTicks`. Для оружия с тем же поведением, что у SMG, можно изменить предметы, количество патронов и ожидаемый набор снарядов в кратком формате `smg.json`. Для других механик используйте формат с массивом `steps`.

1. В `items` перечислите `item`, `quantity` и `slot`. Имена имеют вид `helluvia01/EmberShotgun` или `Terraria/MusketBall`. Инвентарь и экипировка изолируются на время теста. Хотбар занимает слоты 0–9, боеприпасы — 54–57. Для выбора используйте `selectedSlot`. Стенд проверяет фактический тип и количество после выдачи. Большая партия распределяется по доступным слотам с учётом `maxStack`.
2. В `accessories` можно указать начальную экипировку в доступных функциональных слотах 3–9. Чтобы измерить эффект относительно исходного состояния, используйте `sample`, затем `equip` и `await` с `relativeTo`, как в `melee.json`.
3. Через `initial` задаются `health`, `mana`, абсолютный центр игрока `position: [x,y]` либо смещение от спавна `spawnOffset`. Координаты в пикселях. `target` принимает внутреннее имя NPC, `offset` относительно центра игрока и `health`. Стенд фиксирует положение именно этой мишени и регистрирует попавшие в неё атаки тестового игрока.
4. Опишите действия и ожидаемые измерения. Укажите `requireAttack: true`, если обязательно должен сработать игровой обработчик использования предмета. Для теста запрета можно ожидать `attacks == 0` после зарегистрированного нажатия.
5. Запустите новый файл через `--scenario`. Проверьте `report.json`, последовательность событий и кадры. Для нового оружия с подходящими метриками достаточно JSON.

| Действие `op` | Поля и смысл |
| --- | --- |
| `press` | `button` равен `primary` или `alternate`, `aimOffset: [dx,dy]` в мировых пикселях от игрока, `ticks` — длительность удержания. После интервала кнопка отпускается, проверяется фронт нажатия. |
| `hotkey` | `name` — триггер Terraria либо полное внутреннее имя зарегистрированного `ModKeybind`. Проверяется реальный фронт игровой команды. Эффект клавиши задаётся отдельным утверждением. |
| `select`, `give`, `equip` | Выбор слота хотбара, выдача предмета либо помещение аксессуара в функциональный слот во время сценария. |
| `wait` | Пауза на `ticks` обновлений симуляции перед следующим действием. |
| `assert`, `await` | Проверить `metric` немедленно или дождаться условия за `timeout` тиков. Требуется хотя бы одна из границ `eq`, `min`, `max`. |
| `sample` | Запомнить `metric` под `name`. Утверждение с `relativeTo` проверяет разницу с сохранённым значением. |
| `kill`, `respawn` | Реальная смерть через `Player.KillMe`, затем ускорение таймера штатного возрождения. После `respawn` дождитесь `respawnCount` или состояния `dead == 0`. Hardcore для этого действия не подходит. |
| `capture` | Запрос кадра с уникальным `name`. Допустимы латинские буквы, цифры, дефис и подчёркивание, до 48 знаков. |

Доступные метрики включают `attacks`, `animation`, `selectedSlot`, `stack/<номер слота>`, `buff/<имя мода>/<имя баффа>`, `spawned/<мод>/<снаряд>`, `killed/<мод>/<снаряд>`, `life`, `mana`, `dead`, `deathCount`, `respawnCount`, `target.life`, `target.hits`, `target.damage`, `player.statDefense`, `player.lifeRegen`, `player.moveSpeed`, `player.lifeMax`, `player.manaMax`, `player.x` и `player.y`. Счётчики снарядов в пошаговых сценариях относятся к снарядам, созданным от текущего предмета тестового игрока. Для дочерних снарядов с другим источником потребуется дополнительный наблюдатель.

Для нового внутреннего состояния добавьте в `ScriptScenario.Metric` измерение только для чтения и укажите его в JSON. Метрика `helluvia01/EmberShotgun.cooldown` вызывает существующий метод мода `ShotSession.Remaining(Player)`. При смене его имени или сигнатуры потребуется обновить этот адаптер. Проверки урона и игровых событий расширяются через хуки в `WorldFixture.cs` и `ScriptScenario.cs`.

## Результаты запуска

В `report.json` записываются сценарий, статусы стадий, реальные события, ожидания, измерения, ошибки, пути к журналам и кадрам. Стадии без полученных событий помечаются `skipped`. Несовпадение игровой проверки даёт `failed`. Если сборка не прошла, упал клиент, пропала связь или истёк внешний тайм-аут, общий результат остаётся `inconclusive`. Для тайм-аута клиента передайте время в секундах через `--timeout`. В JSON сценария тайм-ауты задаются в игровых тиках.

В папке запуска сохраняются `build.log`, `client.log`, журнал игровых событий `events.jsonl`, результат тестового мода `result.json`, подтверждённые PNG и, при доступности, штатный журнал `loader-client.log`. Тик события `capture` и тик фактической отрисовки `frame` могут различаться. Если чтение backbuffer недоступно, запасной путь захватывает только собственное активное окно и отмечает, что кадр снят позже. Для пропорций оружия, свечения, прозрачности и анимации предусмотрена визуальная проверка сохранённых кадров. Каждый кадр получает отдельный `visualStatus: inconclusive`.

Сценарии запускаются в одиночной игре. Для сетевой авторитетности, синхронизации и задержек нужен отдельный сценарий с сервером и клиентами. Эта версия использует стандартные слоты Terraria и имеющиеся локальные тестовые сохранения. Генерация мира, облачные сохранения и аксессуарные слоты сторонних модов в текущий прогон не входят.
